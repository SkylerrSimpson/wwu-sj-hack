# Decisions

One line each: what, why, what it replaced. Append only.

- 2026-11-04 Next.js + Tailwind + shadcn on Vercel for the product, Python for the data. Each owner works in the stack they already know, and the deploy needs no configuration. Replaced: a shared backend.
- 2026-11-04 `data/` writes a static `apps/web/public/data.json` that the app reads at build time. One file is the whole integration, and the demo cannot fail on a dead service. Replaced: an API between the halves, and a database. Revisit only if users have to write data.
- 2026-11-04 `data/schema.json` (JSON Schema) is the contract between the halves; `make check` validates the file against it, and the schema refuses undeclared fields. Readable by both languages and both people. Replaced: an agreement kept by hand.
- 2026-11-04 pnpm workspace, TypeScript 7 with `noUncheckedIndexedAccess`, oxlint with type-aware rules, Prettier at width 100, Vitest at the root. TypeScript 7 has no JavaScript compiler API, so type-aware ESLint rules cannot run against it; oxlint's type-aware mode is built on the same compiler. Replaced: ESLint.
- 2026-11-04 Python is formatted and linted by ruff and type-checked by mypy, so both halves have the same kind of gate. Replaced: unchecked Python.
- 2026-11-04 `uv` runs the Python side (`uv run`, `uv sync`). One tool that behaves the same on every machine and fetches Python itself. Replaced: venv + pip.
- 2026-11-04 Commits land on `main` by rebase, and the pre-commit hook runs the full `make check`, `next build` included. Two owners in two folders; a review queue costs more than it catches in one day, so the hook is the review. Replaced: pull requests.
- 2026-11-04 The Vercel build type-checks. There is no CI, so the deploy is the second gate after the hook. Replaced: skipping type errors at build time.
- 2026-11-04 Tests on core logic and the data contract only; the demo path is checked by a person walking the live deploy after each landing. Replaced: browser end-to-end tests.
- 2026-11-04 `data.json` carries no build timestamp, so `make data` is byte-reproducible and a test proves the committed file is what `build.py` produces; freshness is each source's `retrieved` date. Replaced: a `generated_at` field.
- 2026-11-04 shadcn's current default style (`base-nova`, on Base UI), the `cn` package, and Tailwind through `@tailwindcss/turbopack`. Base UI composes with a `render` prop where Radix took `asChild`. Replaced: the Radix-based shadcn setup.
- 2026-11-04 Next's cache components are off, so the page uses the rendering model every reference assumes. Replaced: create-next-app's `cacheComponents: true`.
- 2026-11-04 Decisions live here, one line each. Replaced: architecture decision records.
- 2026-11-04 Docs are split by reader: `docs/` for people (setup, the weekend, spec, decisions) and `agents/` for coding agents (standards, skills, kickoff), with `AGENTS.md` at the root as the agents' entry point. Replaced: one pile of markdown at the root.
- 2026-11-07 One day, not a weekend: 10:00 to a 16:00 deadline, four people, freeze at 14:00, review against the starter commit `90ab845`. The event schedule was one day; the docs assumed Fri to Sun. Replaced: the `friday` tag and the Sunday pitch.
- 2026-11-07 Challenge 1, Lummi vessel monitoring. One pure rule set over public data fits a day, and the data scientist's strength is data collection. Replaced: the attorney-matching and basic-needs challenges.
- 2026-11-07 Replay one recorded day of AIS, not a live feed. The static `data.json` design stands, nothing can fail at demo time, no key is exposed; the visit rules don't change when a feed is added. Replaced: aisstream.io live.
- 2026-11-07 The AIS source is NOAA's daily file, streamed and boxed in `fetch()` with the stdlib. It downloads directly and needs no order queue or dependency. Replaced: AccessAIS orders, and GeoParquet with duckdb.
- 2026-11-07 The boundary is the Census Lummi Reservation polygon (GEOID 2070R), cited with WDFW's closure line, labeled approximate. It is public domain and matches the Nation's own layer within 0.1 km²; that layer may not be reproduced without consent. Replaced: a hand-drawn polygon.
- 2026-11-07 Inside-the-boundary is plain Python ray casting over one ring. Replaced: shapely or geopandas.
- 2026-11-07 The pipeline computes visits; the web app displays them. The rules live in one tested place and `data.json` stays small. Replaced: shipping raw positions to the browser.
- 2026-11-07 Identities are stripped in `fetch()` before anything is saved: names, IMO and call signs dropped, each MMSI mapped to `V001…`, the mapping never written. `data/raw/` is committed and public. Replaced: pseudonymising after the raw save.
- 2026-11-07 The approved list is invented and includes every real vessel seen; only a synthetic vessel, in its own source, is unlisted and flagged. The real list is the Nation's, and flagging a real boat against an invented list would be a false statement. Replaced: flagging real vessels.
- 2026-11-07 Approved vessels are summarised one line each on the home page; flagged visits are listed one by one. The ferry crosses the boundary 26 times a day and would bury the flagged visit. Replaced: one card per visit.
- 2026-11-07 One static page per visit via `generateStaticParams`, the browser holding no state. Links and the back button just work. Replaced: a selected visit in client state, and `?visit=` query params, which make the page dynamic.
- 2026-11-07 Times stored in UTC, shown in America/Los_Angeles with `Intl.DateTimeFormat`; the file's window shown in local time. Replaced: a date library, and presenting a UTC day as "a day".
- 2026-11-07 `leaflet@1.9.4` with `@types/leaflet`, OpenStreetMap tiles with attribution, and shadcn `badge`. The demo's key moment is a track crossing a boundary, which needs a map; 1.9.4 is the stable release (2.0 is a week-old beta). Replaced: react-leaflet (a wrapper for one map), MapLibre (heavier), a hand-drawn SVG (the fallback if the map is cut).
- 2026-11-07 Data-format changes are agreed out loud between Willow and Skyler, with the landing order unchanged (data side first for an added field). The team sits together, so an issue and an `agreed` comment were ceremony. Replaced: the schema-issue protocol.
- 2026-11-07 The team's plan, Lummi Vessel Tracker: a map replaying the event's five days of AIS, ships as dots, a priority list, and an email alert when a non-priority vessel enters Lummi waters. It replaces the morning's draft of a visit list with per-visit record pages, and the lines above that belong to it (the one recorded NOAA day, visits computed in the pipeline, stripping all identities, summarising approved vessels, one static page per visit).
- 2026-11-07 The data is the event's AIS file and boundary KML. The KML agrees with the Census Bureau's reservation polygon on all 219,863 positions. Replaced: the NOAA daily download and the Census polygon.
- 2026-11-07 `page.tsx` imports `data.json` at build time and passes it to the client map as a prop (about 3.7 MB at one position per vessel per 5 minutes). One typed path, and `make check` still proves the file matches the types. Replaced: the browser fetching `/data.json`.
- 2026-11-07 Entry detection runs in the browser on each replay tick, as pure functions in `lib/vessel.ts`; it's what a live system would run on each new position. Replaced: entries computed ahead of time in `build.py`.
- 2026-11-07 Email alerts go through Resend from a server function, with the key in an environment variable. Resend's test sender only delivers to the account owner's inbox, which also stops the public form being used for spam. It's the app's only runtime call besides map tiles. New dependency: `resend`. Replaced: a fully static app.
- 2026-11-07 The alert email is kept in the browser's local storage. Replaced: accounts and a database.
- 2026-11-07 Commercial vessels show their AIS name; private boats (AIS types 36 and 37) show only type and length. AIS is public, but a private boat's name identifies its owner, and `data/AGENTS.md` keeps personal data out of `data.json`. Replaced: pseudonyms for every vessel.
- 2026-11-07 The priority list is invented and lives in `data/`; one labeled synthetic vessel, not on it, makes the demo alert fire. Real data has no non-priority vessel entering Lummi waters. Replaced: alerts on real vessels.
- 2026-11-07 Leaflet with OpenStreetMap tiles. Replaced: Google Maps, which needs a billing account and a public key.
- 2026-11-07 Vessel statuses: priority (an AIS name or call sign containing XWL, WSF, SWN or NKK, the explicit list, or the officer's additions), watch list (the officer's additions only), unlisted (everyone else); suspicious is an unlisted vessel that has entered. "Watch list", never "known offender": the tool cannot verify an offence, and the alert wording stays the officer's call. Replaced: one priority flag.
- 2026-11-07 The officer's additions to either list live in the browser's local storage, keyed by vessel id. Replaced: a database and accounts.
- 2026-11-07 Fishing boats are anonymised like sailing and pleasure boats, with ids `private-n`, and the committed raw file is stripped the same way. A real fishing boat with a Lummi name showed as "unlisted" in a tool about flagging fishing boats, and MMSIs are reversible through any AIS lookup. Replaced: naming every commercial vessel.
- 2026-11-07 The synthetic vessel crosses in twice, an hour apart, so the demo shows a suspicious alert and then a watch-list alert. Replaced: one crossing.
- 2026-11-07 Vessels get a `fleet` label (Lummi Nation, Washington State Ferries, Swinomish, Nooksack, Whatcom County ferry, or the list's label) so the app can say what kinds of vessels are in Lummi waters, which the PM asked for. Replaced: the priority flag alone.
- 2026-11-07 Deploy to Vercel at the first opportunity, not after the freeze: the stack (pnpm 12, Node 24, TypeScript 7, a workspace root) is untested there. Replaced: the D-1:30 slot.
- 2026-11-07 The priority patterns are applied in the browser from the officer's configuration, with XWL, WSF, SWN and NKK as defaults, and the officer can add or delete patterns and approve ids in the app. The data bakes in only the explicit two-vessel list and each vessel's call sign. Baking the patterns into the data would make deleting one in the app do nothing. Replaced: patterns applied in `build.py`.
- 2026-11-07 The configuration UI is built from shadcn components (Card, Table, Input, Label, Button, Badge), customised in place, so the officer's part of the app looks designed rather than generated. Replaced: hand-written form markup.
- 2026-11-07 The user-facing word is "approved" (approved vessel, approved list) and the user is "Lummi Nation staff", not "the officer": the Nation's Natural Resources staff will use it, not only police. The code keeps the `priority` identifier to avoid churn. Replaced: "priority" and "officer" in copy.
- 2026-11-07 `Replay` fetches `/data.json` at runtime instead of receiving it as a prop. The prop embedded 4 MB twice, in the HTML and the RSC payload, and `next build` hit its 60 s page timeout once; the static file is one cacheable request. Replaced: the build-time prop.
- 2026-11-07 Live vessels come from AISStream through a Python service on a team home lab. It is the only free source that works today with no receiver or sign-off, and it heard the Lummi Island ferry in testing. It has no uptime guarantee and updates each vessel about every 1 to 3 minutes, so `aisstream.py` is the only code that knows the provider, and a receiver the Nation owns or a paid API is the upgrade if this gets real use. Replaced: recorded data only.
- 2026-11-07 The streamer is its own Python project in `apps/streamer`, using `aiohttp` for the feed connection and the HTTP server. One dependency covers both, and a long-running connection can't live in the `data/` build script or on Vercel. New dependency: `aiohttp`. Replaced: a Node collector.
- 2026-11-07 The live stream uses Server-Sent Events. It only flows one way, and browsers reconnect and resume by themselves. Replaced: WebSockets to the browser.
- 2026-11-07 Live records follow `data/build.py`'s privacy rule, and a vessel of unknown type is private until its type arrives. Ids are a keyed hash of the MMSI, so a client can follow a boat without learning who owns it. Impossible jumps are flagged, not hidden, since they can mean a false identity. Replaced: publishing MMSIs for every vessel.
- 2026-11-07 Synthetic radar, thermal camera and LIDAR (nonais/generate.py) load from their own file, apps/web/public/sensors.json, only when the officer switches them on, so the AIS replay never depends on them. A radar track is identified when one AIS vessel sits within 300 m of at least half its fixes; otherwise it is "unidentified, radar only", alerts as such, and is never named. The app's copy holds no ground truth; nonais/sensors.json keeps it for scoring the match. Replaced: radar as the "next" slide only.
- 2026-11-07 The non-AIS proof of concept uses radar and LIDAR only; LIDAR alone corroborates a radar contact. Replaced: a thermal camera at Gooseberry Point.
- 2026-11-07 The web app has a Live mode next to the recorded replay: `EventSource` on the streamer's `/v1/stream`, the same rules run on the live tracks with the wall clock as `t`, and the feed's status and age shown on screen. The recorded replay stays the demo path. Replaced: recorded data only.
- 2026-11-07 Radar is shown as coverage only: a "Show radar coverage" tick box draws four hypothetical shore radar sites along the Lummi coast (Sandy Point, Gooseberry Point, Portage Island, Lummi Shore Road) with an assumed 6 km range for a small boat. No synthetic boat, no matching and no alerts, so nothing on screen is invented except the sites. nonais/ is left as research data the app no longer reads. Replaced: the synthetic radar contact, its unidentified alert, and LIDAR.
- 2026-11-07 A redesign for the afternoon: `/` is a sign-in screen, `/map` a map-first tracker with a thin top bar and a collapsible tabbed column, `/settings` holds every configurable thing. The team wants it to read as a modern application the Nation could run; the Look section of the spec fixes the rules. Replaced: one page with the map and three cards.
- 2026-11-07 Sign-in is a demo gate: one shared password from the environment, an httpOnly cookie, and `proxy.ts` guarding `/map` and `/settings`. Accounts need a database, which is out of scope; the gate still gives the demo its login moment and the pitch says what it is. Cloudflare Turnstile is an issue for later. Replaced: no sign-in at all.
- 2026-11-07 Added shadcn tabs, separator, tooltip and switch for the redesign. Replaced: hand-written equivalents.
